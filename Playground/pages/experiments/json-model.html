The document model, exercised: pointer addressing, pure structure mutations, the single writer, type conversion, and undo. No view, no DOM — the whole layer is testable on its own.

applyEdit() is the only function that produces a new document. It clones, lets you mutate, serializes, then parses the text back and refuses the edit unless it matches. If it refuses, the text has not changed. The cases below prove that, rather than assuming it.

Why the re-parse

The round-trip suite proved the fixtures survive a serialize → parse cycle. It cannot prove the next shape someone adds, or the next edit. Re-parsing on every commit costs one extra parse of a config-sized document and converts the next silent corruption into a thrown error with the text unchanged — which is the difference between a bad file and a refusal.
