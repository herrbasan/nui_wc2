JSON grid

The value-shaped grid. The shape of a value decides how it renders: scalars inline, arrays of scalars as an indexed sub-table, objects as a key/value sub-table, and arrays of objects as the only shape that gets a header.

Ready.

Grid

Adding is one click. Every list ends with + Add one more, and so does every branch head. The new value inherits the type of the one before it and takes a name that continues the document's own numbering — id1, id2 invites id3, not id1_2. No dialog, because a dialog per row is a dialog per row and adding twenty properties is the case that matters.

If the inherited type is wrong, click the type chip and change it. The type badge displays what the format's own reader makes of the text; it does not constrain it. Type 4096 into a string cell and it becomes a number, because the text is the truth.

A conversion that would discard something is refused and says so. An empty container converts freely — it holds nothing — which is what makes add-then-retype a two-click operation.

The text

This is the document. The grid is a view of it, and every edit above rewrote this text and re-read it. A structural edit re-serializes, so formatting the YAML writer chose is what you get back — but nothing is ever changed except through here.







	
What the grid is not

	

		
No grips, no selection chrome, no context menu, no +
		affordances. nui-table-editor showed that chrome belongs on
		selection, not on hover — so a grid at rest shows the resting state, and
		the handles arrive with the next slice.

		
No Code/Tree/Table/Grid tabs either. The grid is the unit; the
		four-view chrome is a host's concern until something needs the composite.
