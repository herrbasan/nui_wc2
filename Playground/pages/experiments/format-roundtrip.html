Format round-trip

Property test for the format layer: for every shape the grid can put on screen, does the text survive a serialize → parse round trip — in every supported format?

The grid's text owns the document, so every structural edit is mutate → serialize → set text → parse → render. If a value cannot survive that cycle the editor corrupts the user's file silently: no error, no exception, just a document that quietly stops matching what the grid shows.

The same fixtures run against every registered format, because the grid itself is format-agnostic — format enters at exactly two seams, parse and serialize. A gap in one format is a gap in the editor, even when the other format is clean.

What the two formats actually are

JSON is total. JSON.parse throws on malformed input and reports a position; JSON.stringify round-trips every value a grid can hold. Nothing there can fail — which is why the JSON column shows no failures at all.

YAML is a subset. It round-trips everything it emits, which took four fixes to the parser in NUI/nui.js — all of them silent corruption, none of them visible by reading the code. It does not support block scalars (|, >), flow mappings ({a: 1}), anchors, multiple documents, tags, or date scalars.

And it does not report errors. parseYaml is best-effort: a line it cannot read ends a block, a bad indent yields null, and it returns a partial structure instead of throwing. A try/catch around it catches almost nothing. That is why verifyYaml() exists — an editor cannot rely on a parse failure to notice a broken document.

One accepted gap, and it is format-specific. A bare scalar root survives JSON ("hello" parses straight back) and is unrepresentable in this YAML subset (hello reads as {}). assertEditableRoot() rejects it in both, at the editor's boundary, rather than the shared parser changing behaviour for every markdown file that happens to have odd frontmatter.
