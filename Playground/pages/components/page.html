Page Component

The content layout engine — readable max-width by default, breakout for full-width sections.

What It Is

<nui-page> is the wrapper the router creates automatically for every loaded fragment — you rarely author it yourself. It solves a reading problem: long lines on wide screens are hard to read, so every direct child is constrained to --space-page-maxwidth (~56rem), while any child carrying the breakout attribute spans the full container width.

This demo page is itself rendered inside a router-created <nui-page> — the constrained columns you see here are the component working.

Constrained vs. Breakout

The first block below is an ordinary constrained child. The second carries breakout and spans the full content width.

Caveat this demo has to cheat for: a breakout child is only as wide as its container. A <nui-page> nested inside a constrained column makes breakout invisible — both children render at the container's width. So the fragment root itself carries breakout against the outer page; the nested page then has real width to demonstrate against.

Constrained child — capped at the readable max-width, like all default children.

Breakout child — spans the full container width via the breakout attribute.

Re-constraining with .maxwidth-container

When a section breaks out for a full-bleed background, its content loses the readable constraint. Wrap the inner content in .maxwidth-container to re-apply it — full-bleed surface, readable text.

Breakout surface, constrained content. The shaded area spans the full width; this text sits back inside the readable column.

Router Integration

The router creates the wrapper for you: navigating to #page=components/page fetched this fragment, wrapped it in <nui-page class="content-page ...">, injected the HTML, and upgraded the elements. On later visits the cached wrapper is shown and hidden — init() does not run again.

If a fragment must opt out of the page wrapper's layout behavior, give it a plain <div> root instead of relying on the wrapper.
